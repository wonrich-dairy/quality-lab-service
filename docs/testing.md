# Testing and code coverage

How Quality Lab Service runs its tests and measures coverage (SCRUM-42). The other Wonrich services follow the same pattern; the last section is a copy-and-adapt checklist.

---

## Test projects

| Project | Kind | What it covers |
|---|---|---|
| `tests/QualityLab.UnitTests` | Unit | Logic in isolation, no I/O. Fast (seconds) |
| `tests/QualityLab.IntegrationTests` | Integration | The real API through HTTP (`WebApplicationFactory`) against a throwaway MySQL started by Testcontainers. Also proves EF Core migrations run on an empty database |

They are separate projects, and separate **named CI stages**, so a slow integration failure is never confused with a broken unit.

```bash
dotnet test tests/QualityLab.UnitTests            # fast feedback while coding
dotnet test tests/QualityLab.IntegrationTests     # needs Docker running locally
```

The integration tests need Docker Desktop; Testcontainers starts `mysql:8.0` and removes it afterwards. No connection string or `.env` is needed: the container's own connection string is injected into the app.

Kafka is not available in CI, so the Kafka health check reports **Degraded** there. That is asserted by the tests rather than worked around.

## Coverage

| Item | Value |
|---|---|
| Collector | Coverlet (`--collect:"XPlat Code Coverage"`) |
| Settings | `coverlet.runsettings` (Cobertura format; excludes `Data/Migrations` and generated code) |
| Report | ReportGenerator merges the unit and integration runs into one report |
| Threshold | **60% line coverage**, enforced in CI; a drop below it fails the build |
| Artifacts | `coverage-report` (HTML), `test-results` (`.trx`) |

EF Core migrations are excluded because they are generated by tooling; including them would measure the generator, not the team's tests.

### Where to read it

| Where | What you see |
|---|---|
| Pull request comment | Coverage summary table, updated in place on each push |
| Actions run summary | The same table |
| **Test results** check | Every test, with failures readable in the UI rather than the raw log |
| `coverage-report` artifact | Full HTML report: download, open `index.html`, drill into per-file and per-line coverage |

### Changing the threshold

`COVERAGE_THRESHOLD` in `.github/workflows/ci-cd.yml`. Raise it as the codebase grows; agree the number with QA first. It starts at 60% because the service is still mostly scaffolding; the intention is to raise it in Sprint 4.

---

## Adding tests

- **Unit:** add a class to `tests/QualityLab.UnitTests`. No database, no network, no Kafka.
- **Integration:** add a class to `tests/QualityLab.IntegrationTests` that takes `QualityLabApiFactory` as an `IClassFixture`, and call the API through `factory.CreateClient()`.

Fix a failing coverage check by adding tests, not by lowering the threshold.

## Copy-and-adapt checklist for the other services

1. **Two test projects**, `<Service>.UnitTests` and `<Service>.IntegrationTests`, added to the solution.
2. **Integration packages:** `Microsoft.AspNetCore.Mvc.Testing`, `Testcontainers.MySql`, `coverlet.collector`.
3. **`public partial class Program { }`** at the end of `Program.cs`, so `WebApplicationFactory<Program>` can find the entry point.
4. **Copy `coverlet.runsettings`** and adjust the migrations path to match your project layout.
5. **Copy the test and coverage steps** from `.github/workflows/ci-cd.yml`:
   - the two named stages, **Unit tests** and **Integration tests**, each with `--settings coverlet.runsettings --collect:"XPlat Code Coverage"` and a `.trx` logger
   - `dorny/test-reporter` for the `.trx` files
   - `danielpalme/ReportGenerator-GitHub-Action` (`HtmlInline;Cobertura;JsonSummary;MarkdownSummaryGithub`)
   - artifact uploads, the step summary, the sticky PR comment, and the threshold check
6. **Job permissions:** `pull-requests: write` and `checks: write`.
7. **Same threshold**, so the services are comparable. Currently **60%**.
8. **Branch protection:** require the **Build and test** check before merging.

Frontend (`npm test`) follows the same rules: coverage collected, HTML report uploaded as an artifact, and the same threshold enforced.
